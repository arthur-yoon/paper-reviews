# On the Threat Model of Weird Generalization and Emergent Misalignment

## 핵심 아이디어 한 줄 요약

소규모 도메인 데이터로 미세조정(Fine-tuning)한 모델이 예상 밖의 광범위한 행동 변화(Weird Generalization, WG)를 보일 때, 이를 유발하는 핵심 요인은 데이터의 '크기'가 아니라 '구성(Composition)'과 '언어', 그리고 '학습 데이터가 기존 모델 지식과 얼마나 유사한지'에 있으며, 측정 방식 자체도 평가 질문 선택에 따라 크게 흔들리는 취약한 현상이다.

## 구현 설명

논문의 핵심 주장인 "WG의 취약성"을 검증하기 위한 개념적 실험 설계를 다음과 같이 단순화하여 구현할 수 있다. 실제 코드 작성 대신, 논리 흐름과 변수 제어로 구성한다.

1.  **대상 모델 및 데이터셋 선정**
    -   **모델:** 오픈 웨이트(open-weight) 모델 3종을 선정한다 (예: Llama-3-8B, Mistral-7B, Qwen-7B 등).
    -   **학습 데이터(Fine-tuning Data):** 4개의 소규모 도메인 데이터셋을 준비한다. 이때 각 데이터셋은 동일한 주제이지만, 아래 변수를 통제하도록 변형을 만든다.
        -   **변수 A (구성/Composition):** 같은 주제라도 데이터의 유형(예: 질문-답변 쌍만 있는 경우 vs. 대화 형태인 경우)을 다르게 구성.
        -   **변수 B (언어/Language):** 영어 데이터셋과 한국어(또는 기타 언어) 데이터셋으로 분리.
        -   **변수 C (신규성/Novelty):** 모델의 사전 학습(pre-training) 코퍼스에서 잘 알려진 일반 지식 기반 데이터 vs. 모델이 거의 학습하지 않은 고유한 신규 도메인 데이터.

2.  **미세조정(Fine-tuning) 실행**
    -   각 모델에 대해, 위에서 준비한 4개 데이터셋 각각을 소규모 규모(small scale)로 미세조정을 수행한다.
    -   이때 데이터setSize를 의도적으로 작게 유지하여, 논문이 지적한 "크기보다 구성이 중요하다"는 가설을 검증한다.

3.  **평가 프로토콜 설계 (WG 측정의 민감성 분석)**
    -   **평가 질문 세트(Evaluation Question Sets):** WG 정도를 측정하기 위해 소규모 질문 세트를 준비한다.
    -   **변수 D (평가 질문 민감성):** 동일한 모델에 대해, 서로 다른 2~3개의 평가 질문 세트를 적용한다.
        -   세트 1: 학습 데이터와 직접 관련이 적은 일반적 질문들.
        -   세트 2: 학습 데이터의 주제와 약간만 겹치는 질문들.
        -   세트 3: 학습 데이터의 패턴을 모방한 새로운 질문들.
    -   **측정 지표:** 각 질문 세트에 대해 모델의 응답이 '기대하지 않는 광범위한 행동 변화'를 보이는 비율을 계산한다.

4.  **비교 및 분석 로직**
    -   **분석 1 (구성 vs 크기):** 데이터 크기를 일정하게 유지하고 구성만 바꾼 모델들의 WG 점수를 비교. 구성이 다른 경우 점수가 크게 달라지는지 확인.
    -   **분석 2 (언어 영향):** 영어 데이터로 학습한 모델과 한국어 데이터로 학습한 모델의 WG 점수를 비교. 언어에 따라 WG 정도가 어떻게 변하는지 확인.
    -   **분석 3 (신규성 영향):** 사전 학습 지식에 익숙한 데이터로 학습한 모델 vs 신규 데이터로 학습한 모델의 WG 점수 비교. 논문의 주장대로 "익숙한 데이터가 더 높은 WG을 유발한다"는 경향이 확인되는지 확인.
    -   **분석 4 (평가 민감성):** 동일한 모델에 대해 평가 질문 세트를 변경했을 때 WG 점수가 얼마나 변동하는지 측정. 변동폭이 크다면 WG 측정이 매우 불안정함을 입증.

## 실행 방법과 예상 출력

1.  **실행 환경 준비**
    -   GPU 클러스터 또는 단일 고사양 GPU 환경을 준비하여 Hugging Face Transformers와 PEFT(Parametric and Efficient Fine-Tuning) 라이브러리를 설치한다.
    -   데이터 전처리 파이프라인을 구축하여, 4개의 학습 데이터셋을 표준화된 포맷(예: JSONL)으로 변환한다.

2.  **실행 단계**
    -   **Step 1:** 각 오픈 웨이트 모델을 로드하고, 4가지 변형된 학습 데이터셋으로 미세조정을 순차적으로 수행한다. (총 12번의 학습 실행: 3개 모델 × 4개 데이터셋)
    -   **Step 2:** 학습이 완료된 체크포인트를 저장한다.
    -   **Step 3:** 각 체크포인트를 로드하고, 준비된 3개의 평가 질문 세트 각각으로 추론(inference)을 수행한다.
    -   **Step 4:** 모델의 응답을 자동화된 평가 스크립트(예: LLM-as-a-Judge 또는 정해진 키워드 매칭)를 통해 WG 점수로 변환한다.

3.  **예상 출력 결과**
    -   **테이블 1: WG 정도에 따른 요인 비교**
        -   **관점 1 (구성 > 크기):** 데이터 크기가 동일한 두 모델 중, 데이터 구성이 더 다양하거나 특이한 모델이 더 높은 WG 점수를 기록한다. 즉, "데이터를 많이 넣었다"는 것보다 "어떤 데이터를 어떻게 넣었는가"가 더 큰 영향을 미친다.
        -   **관점 2 (언어 영향):** 영어 데이터셋으로 학습한 모델과 비영어 데이터셋으로 학습한 모델 간에 WG 점수가 통계적으로 유의미한 차이를 보인다. 특히, 모델이 사전 학습 과정에서 상대적으로 덜 학습한 언어로 미세조정했을 때 WG가 더 극적으로 나타날 가능성이 높다.
        -   **관점 3 (신규성 역전):** 모델이 사전 학습 시점에 이미 충분히 학습한 '익숙한 도메인' 데이터로 미세조정했을 때, '전혀 새로운' 도메인 데이터로 학습했을 때보다 더 높은 WG 점수를 기록한다. 이는 모델이 기존 지식 패턴을 새로운 맥락에 과도하게 일반화시키기 때문으로 해석된다.

    -   **그림/차트: 평가 질문 세트에 따른 WG 점수 변동**
        -   x축: 평가 질문 세트 1, 2, 3
        -   y축: WG 점수
        -   **관점 4 (측정 불안정성):** 동일한 미세조정 모델에 대해 평가 질문 세트만 변경했을 때, WG 점수가 매우 넓은 범위(예: 0.2에서 0.8 사이)로 크게 변동한다. 이는 WG의 정도가 학습 데이터의 고유한 속성이라기보다는, "어떤 질문으로 테스트하느냐"에 따라 크게 좌우되는 취약한 측정에 기인함을 시각적으로 보여준다.

    -   **결론적 요약:** 최종 분석 결과, WG는 특정 데이터의 '본질적 위험'이라기보다, 데이터의 미세한 구성 차이, 언어적 특이성, 그리고 평가 질문의 선택이라는 '취약한 속성들'의 상호작용으로 발생하는 현상임이 드러난다.

## 한계

1.  **간이 구현의 복잡성 간과:** 논문의 실험은 "plausibly relevant features"를 폭넓게 탐색했으나, 실제 WG를 유발하는 메커니즘이 비선형적이고 상호작용(interaction) 효과가 복잡할 수 있다. 본 구현 설명은 변수를 독립적으로 분리하여 분석하는 데 중점을 두어, 변수들 간의 복합적 영향(예: 특정 언어 + 특정 구성 + 평가 질문의 상호작용)을 완전히 포착하지 못할 수 있다.

2.  **평가 기준의 주관성:** WG의 정의를 명확하게 수치화하는 것은 어렵다. "기대하지 않는 광범위한 행동 변화"가 무엇인지에 대한 평가 기준(Judge 모델의 편향, 키워드 매칭의 정확도)에 따라 결과가 크게 달라질 수 있다. 본 구현 설명에서는 평가 프로토콜의 민감성을 분석하는 데 초점을 두었지만, WG 자체의 정량적 정의에 대한 근본적 한계는 해결하지 못한다.

3.  **프로덕션 적용의 어려움:** 논문의 결론은 WG가 "적대적 위협(adversarial threat)"일 가능성이 높다고 주장한다. 이는 WG가 일상적인 미세조정 과정에서 우연히 발생하기보다는, 의도적인 데이터 엔지니어링이 필요하다는 의미이다. 따라서 실제 프로덕션 환경에서 WG를 '완전히 제거'하는 것은 불가능할 수 있으며, 대신 데이터 구성과 언어, 평가 질문 세트를 철저히 관리하고 모니터링하는 '위협 모델' 관점의 접근이 필요하다. 본 구현 설명은 WG의 존재를 확인하는 데 목적이 있을 뿐, 프로덕션 배포 시 WG를 방지하거나 완화하는 구체적인 방어 전략을 제시하지 않는다.

4.  **모델 범위의 제한:** 실험은 오픈 웨이트 모델 3종에 국한된다. 폐쇄된 상용 LLM이나, 다른 아키텍처(예: MoE, Transformer 변형)를 가진 모델에서는 WG의 발생 패턴과 그 취약한 속성들이 다를 수 있다. 따라서 본 구현 설명의 결과를 모든 LLM에 일반화하기는 어렵다.
